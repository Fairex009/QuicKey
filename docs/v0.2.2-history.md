# QuicKey v0.2.2: Recent prompts

QuicKey stores the **exact generated text it inserted**, not the entire message read back from ChatGPT. When Start Chat inserts a role-specific setup and the user subsequently inserts a direct, no-role Git Handle with the same keyboard instance, their generated parts are recorded as one complete prompt.

Recent (up to 10): paste (moves item to front), delete one, or clear all with a second confirmation tap. Identical prompts are deduplicated. Bare partial commands, including the FAST+DEEP prefix, are not stored as complete prompts.

Storage: UserDefaults.standard inside the keyboard extension sandbox. No clipboard read/write, network, Full Access, App Groups or additional iPhone app. User-generated text only. In-place update under the same signed bundle identity *should* preserve keyboard-private data, but must be tested on device; deletion or changing identity may lose it. There is no export or cloud backup.

Unrelated clipboard copies cannot change the saved prompts. If the user manually edits a message after insertion, QuicKey has no access to the entire final submitted text and does not represent it as stored.

CI checks exact strings, persistence in an isolated suite, dedup, 10-item cap, deletion and clear. Device acceptance requires in-place update and history persistence after restart and unrelated copies.
